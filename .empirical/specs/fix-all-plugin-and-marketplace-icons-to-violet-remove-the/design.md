# Design

## Approach

1. **Explicit violet in icon assets.** Replace `currentColor` in the two
   installable branding icons that still inherit host text color:
   `plugins/aura/assets/icon.svg` and `plugins/steel-browser/assets/nav-icon.svg`.
   Existing violet icons (`#7c3aed`) and style-forced icons stay as they are.
   Logos remain `currentColor` because they are wordmarks, not plugin icons.
2. **Remove Agent Canvas as a workspace plugin.** Delete `plugins/agent-canvas`,
   drop its `.bb/plugins.json` entry and root README catalog row, then run
   `npm install` so the workspace lockfile stops installing the package.
   Historical `.empirical` records stay untouched.
3. **Align marketplace assets.** In the separate `get-bb/marketplace` checkout,
   rewrite each listing icon owned by this repository to an explicit violet
   `#7c3aed`, including BB Surf. Rename each changed file to the repository's
   content-addressed `<id>-<sha256:8>.svg` convention and update the entry
   reference. Keep BB Surf's ID, display name, Git source, tag prefix, and
   `^0.1.0` range unchanged.
4. **Verify.** Run the focused Aura check, the full workspace `npm run check`,
   a reference scan for Agent Canvas, and the marketplace build. Record the
   rendered color of each changed icon.

## Risks and mitigations

- **Cache-busting:** marketplace icon URLs are content-addressed; keep the new
  filename so clients cannot serve a stale colored asset.
- **Lockfile churn:** run `npm install` rather than hand-editing, then confirm
  no other workspace versions moved unexpectedly.
- **Cross-repo scope:** the marketplace checkout is a separate repository; keep
  its change isolated to icons and one listing, with no tag or source changes.

## Verification plan

- `npm run check --workspace bb-plugin-aura` (focused).
- `npm run check` at the workspace root.
- `grep` scan for retained Agent Canvas install/catalog references.
- `npm run build` in the marketplace checkout.
- Color sample every changed SVG for `#7c3aed`.
