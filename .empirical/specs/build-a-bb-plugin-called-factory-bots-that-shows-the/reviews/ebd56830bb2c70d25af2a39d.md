## Security / correctness

No blocking security or correctness defect. The child replaces a dead process, waits for initialize before tools/call, guards stdin/stdout/stderr, and the board fails closed when a ticket detail cannot be read. Non-blocking: one transient detail failure fails the whole board (F-1), and the displayed start command omits the configured FACTORY_URL (F-2). The MCP child inherits the BB environment (F-3) and stdout/stderr lack error listeners (F-4).

## Design / maintainability

The plugin is split into a config loader, a small stdio JSON-RPC client, pure derivation, a transcript-caching service, and one presentational panel. One poll loop owns board and ticket refreshes. Non-blocking: route changes restart the loop and can briefly overlap an in-flight board read (F-5), BoardSnapshot carries an unused storage path (F-6), lifecycle edge tests are thinner than the code (F-7), the deterministic browser run mocks its RPC data (F-8), the SDK pin follows the repo's 0.4.29 while the running host reports 0.4.21 (F-9), and the shipped factory path is host-specific (F-10).
