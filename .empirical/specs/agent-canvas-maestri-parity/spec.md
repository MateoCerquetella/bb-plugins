# Agent Canvas Maestri Parity

## Goal
Continue the existing independently installable Agent Canvas as a BB-native spatial agent workbench. Reproduce Maestri's publicly observable canvas features, visual proportions, and interaction conventions as closely as BB supports, using live BB threads and real host operations. Full parity means functional behavior, not decorative controls.

## Acceptance Criteria
- [ ] [AC-1] Agent Canvas is catalogued and independently installable; SDK dependency matches its pinned bb-app release; existing workspace plugins remain compatible.
- [ ] [AC-UI-1] [UI] A fine square-grid canvas, floating pill-shaped centered insertion tools, understated node chrome, colored connection cables, workspace sidebar and bottom-right zoom/minimap resemble the inspected reference in light and dark modes. Narrow screens remain usable. Empty workspaces offer a clear insertion action; loading, disconnected, failed-save, unavailable-provider and unavailable-portal states are distinct and retain recoverable user drafts. Sidebar, insertion tools, node actions and library panels are keyboard operable with accessible names, visible focus and appropriate focus return. Small-screen navigation reaches every node through an accessible list or stacked layout rather than clipping a scaled canvas. State and selection remain distinguishable without color alone.
- [ ] [AC-2] Existing live agent chats, recorded parent relationships, worktree filtering, browser capture isolation, offscreen suspension, and bounded recovery continue working without fabricating graph relationships.
- [ ] [AC-3] Users insert, edit, rename, move, resize, duplicate, delete and persist notes, text, drawings, file-tree and portal nodes. Tool plus drag creates a node at the drawn position/size, snapping to 20-unit grid. Locked nodes do not move; blur hides contents; double-click lifts a node and lifted panels can dock left/right.
- [ ] [AC-4] Canvas supports wheel/trackpad pan, pinch/Alt-wheel zoom, middle/Space-drag pan, fit all/selection, selectable minimap with viewport, multi-selection/marquee, copy/paste, Alt-drag duplication, undo/redo, groups/rename/ungroup, six alignments, distribution, tidy and magnetic snapping. Editing text never triggers canvas shortcuts.
- [ ] [AC-5] Users connect/disconnect nodes, distinguish recorded relationships from authored links, traverse links deterministically and cycle attention-needing agents. Connections survive duplication/export/import. Linking alone does not launch or message agents.
- [ ] [AC-6] A reusable role editor stores name/color/instructions. Explicit agent creation selects BB environment, provider/model and role; an explicit send invokes the native BB message API. Per-agent prompt drafts, connected-node mentions and image attachment support use native composition where available. Chat/terminal views use real BB sessions, reporting unavailable PTY capability honestly.
- [ ] [AC-7] Connected notes are readable/editable through bounded plugin agent tools, with contextual access scoped to the invoking BB thread and authorized connection graph. A per-thread Maestro role can recruit/reassign/dismiss teammates using BB operations and exposes observable team status. No background recruitment or destructive deletion occurs merely from opening the canvas.
- [ ] [AC-8] Workspaces retain per-workspace viewport/layout and filters. Floors map to actual BB environments/worktrees and show branch/status. Creating an isolated floor uses supported environment APIs; landing/PR operations produce a reviewable result and require explicit user action.
- [ ] [AC-9] Reusable ensembles (Partituras) and note collections (Fichários) support save/search/rename/delete, placement on another workspace/floor and versioned JSON export/import. Imported data is validated and bounded; thread IDs and process identities are never copied as newly running sessions.
- [ ] [AC-10] File trees read the selected environment, search and preview supported files, and save edits explicitly within the selected root. Browser portals use the project's Steel session for navigation and interaction; they accurately distinguish interactive portals from existing capture-only previews. No arbitrary website iframe is described as guaranteed to embed.
- [ ] [AC-11] Search finds nodes/roles/workspaces/ensembles and focuses results; a shortcuts/settings surface documents and configures navigation/default sizes. Routine scheduling integrates with BB automations where available. Remote work uses enrolled BB hosts rather than new credential storage.
- [ ] [AC-12] Every documented Maestri feature is tracked in parity.md as implemented, adapted with real behavior, unavailable due to a demonstrated host capability limitation, or outstanding. Unsupported native features remain explicit gaps and are never counted as implemented parity. No unfinished portable feature can be silently deferred to mark the goal complete.
- [ ] [AC-13] Meaningful model/authorization/import/history tests pass, root npm install and npm run check pass, plugin build/type checks pass, and installed UI and CLI are exercised in Steel with screenshots. Fresh-context review and Empirical receipts record the actual highest completion level.

## Scope
All portable observable behavior listed above. Incremental implementation is permitted but the feature stays active until all portable acceptance criteria are verified. Import the existing tracked baseline; integrate additions against an independent target only after review and verification. Repository-local tracking remains local-only.

## Non-goals and host-specific adaptations
Copying proprietary source, trademarks, license enforcement, telemetry claims or binary assets into the product is outside scope. Swift/Metal/WebKit internals, APFS clones, Apple Foundation Models/Ombro, macOS Spotlight, native iOS/Android display-buffer streaming and Maestri Wire mobile apps have no direct portable implementation in a BB browser plugin. Record concrete capability gaps and use BB-native equivalents where an actual API exists; do not add fake simulators or imply on-device AI when a cloud agent is used.

## Risks
Persisted-state migrations may damage user layouts: retain prior version and validate the new schema. Imported ensembles must not run shell instructions or start agents implicitly. Host filesystem access must bind to a selected BB environment and deny root escapes. Agent tools must reject unrelated thread access and stale permissions. Browser session scope must remain project-bound. Large canvases must bound reads and virtualize live surfaces. SDK compatibility requires testing all root plugins; keep SDK declarations from the pinned release, never vendored substitutes.

## Verification
Unit tests cover geometry, history, snapping, group/link preservation, validated import, scoped tools and file-root access. Real Steel checks cover insertion, editing, multi-selection, grouping, docking, connections, reload persistence, search, exports and explicit live agent actions. Capture before/after light/dark desktop and narrow viewport screenshots under docs/media. Verify CLI status and bounded tool access on an installed local plugin. Run npm install and npm run check from the root plus plugin types/build checks. Track individual AC evidence rather than asserting full parity from screenshots alone.
